Feedback on the variable: an optional shared instruction prefix placed before the unchanged `{{prompt}}`. Currently it is absent, so the model receives only the raw user question and no harness-specific guidance. The records show that the failures are mostly about how the model handles evidence, citations, and tools, and a prefix is one of the few levers that can shape that behavior across all questions. Below are suggestions for a future prefix arm. None of them change the fixed benchmark questions.

**1. Tell the model to verify before answering when a guide URL is named, and to report what it could not verify.**
- Trace `0a64774c4d8dea93` (web arm, passed) shows the right behavior: the model reported that the search results didn't document a dedicated page and labeled source-based claims.
- Trace `01ee2acc8198192f` (opencode, failed with grading_error) shows the opposite: the model asserted that a specific "editors-and-moderators" page existed and quoted it. Its tool calls failed with "unavailable tool 'invalid'," and it never observed any page content. The final answer presented unobserved content as sourced.
- A prefix line such as "Only attribute claims to a URL you actually retrieved in this session. If a fetch failed or a tool was unavailable, say so and give the answer as unverified from memory" would target this directly.

**2. Separate "answered from memory" from "answered from the guide."**
- Traces `61cf448d7f7cc8c8` and `fca453e1aeba0496` were grounded in fetched guide content and were graded as passing.
- Traces `6965a0c277b10802` (baseline, no tools, failed) and `003716054ea8469a` (baseline, no tools, failed) answered from memory. They gave plausible specific paths (for example `/admin/reports/locked/`-style detail, or a guessed guide slug) with no evidence. The prefix can require that no-tool answers state they are from general knowledge and avoid inventing guide slugs or section names.

**3. Stop fabricated or unverifiable link construction.**
- Trace `6965a0c277b10802` gives guide URLs of the form `…/how-to-guides/` with a note that the slug is unverified. Trace `23ffdcdb54390132` (passed) cites `concepts/scheduled-publishing/`, which matches what was retrieved.
- Add: "Cite only URLs returned by a tool or present in retrieved content. Do not construct URLs from patterns."

**4. Require the cited page to actually contain the claim.**
- Trace `0a64774c4d8dea93` cites a GitHub signal-handler file and an issue (#14652). Those came from search snippets, not page fetches. The answer's deletion-mechanics claims are reasonable but rest on source code the user did not ask for.
- Trace `3b963949db3fa304` (opencode, passed) names shortcuts (`[`, `]`, `Shift+Click`) from a search snippet and a fetched page. The Draftail link is cited from the guide. A prefix could say: "Cite the page that supports each claim. Prefer the user-guide page for user-facing questions, and do not add developer-doc or source-code citations unless asked."

**5. Address the "nothing found" branch explicitly.**
- Trace `0491ca55c0f95e16` (opencode, empty answer, execution_error) produced no answer at all after many tool calls. Its search tool failed with a usage-limit error (status 432), and it then fetched from a developer docs site, read Django template source, and failed on a signed URL.
- A prefix should say: "If your searches fail or return nothing relevant, give a short direct answer with the caveat rather than continuing to search. Always produce a final answer." This addresses the empty-answer failure.

**6. Keep tool use proportionate and within the arm.**
- Trace `30079b324c58f114` (vibe, empty answer, grading_error) made many discovery and shell calls. Several were denied by approval policy, and it never produced an answer. A prefix could say: "Use only the tools this session allows. If a tool is denied, do not retry the same action. Move on to the best available answer."
- Trace `3e49675d44f7f2b0` shows efficient use: one search, one fetch, done.

**7. Calibrate the answer to the question's scope.**
- Trace `27145ad5cea5f3e8` (native+mcp, failed) answered "most recent release" from a search index and an unpopulated releases page. Its claim that 8.1 is the latest is supported only by the release-page fetch. Trace `3e49675d44f7f2b0` gives a precise answer and cites its source.
- Add: "For 'latest' or 'current' questions, state the date or version you verified and whether it could be newer than what you found."

**8. Mind the answer-level behavior the grader rewards.**
- The prefix should ask for the direct answer first, then the link. Several answers (for example `42383817403a7fe0`, a passing run with a Codex-style answer) are good, but some (`5997402443b51c4a`) bury the answer under citation clutter or give a bare URL with no link to the section named.

**Caveats for the optimizer.** Several failures here are tool or provider problems, not prompt problems: rate limits (429), usage caps (432), 404s on guessed guide URLs, signed-URL 403s, and approval denials. A prefix cannot fix those, and it should not be credited for them. The prefix should be tested on its ability to make the model report such failures honestly and still give a final answer. The records also contain a few grader errors (`01ee2acc8198192f`, `30079b324c58f114`, `0491ca55c0f95e16`), so their pass/fail status is not reliable evidence about the prompt. Treat any improvement claim as a hypothesis to test on a fresh sample, not a result.
