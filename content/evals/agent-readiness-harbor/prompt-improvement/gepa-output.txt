## Domain facts to use (verify against the guide where possible)
- **Publishing and moderation:** The action menu shows Publish only to users with publish permission for that page. Users without it see Save draft and "Submit to workflow" (older versions: "Submit for moderation"). Approvers (by default Administrators and Moderators) approve or request changes. Approving the final task publishes. A page in moderation locks for editing. Moderators can publish directly and approve others' submissions; editors can only create drafts and submit them; neither editors nor moderators can access the Settings section. Administrators have full access.
- **Scheduled publishing:** Open the page, use "Set schedule" in the Status side panel, set the "Go live at" date/time, then click Publish. Saving a draft does not schedule it. A scheduled page locks itself until it goes live. Expiry (go-live/expiry) unpublishes a page at a set time and its status becomes Expired.
- **Page status values:** Draft, In moderation, Scheduled, Expired, Live, Live + Draft, Live + (another status).
- **Page privacy:** Users with publish permission click "Change privacy" in the status panel. Options: Public; accessible to any logged-in users; accessible with a shared password (stored in plain text, not for sensitive content); accessible to users in specific groups (most restrictive). Restrictions apply to the page and its child pages.
- **Locked pages:** Admin → Reports → Locked pages shows locked pages with the date/time each was locked. It is a default report usually restricted to Administrators. Locking/unlocking also appears in the Site history report. Dashboard panels may show your own locks.
- **Reports (default):** Locked pages, Workflows, Workflow tasks, Site history, Aging pages (oldest to newest, useful for finding stale content); later versions add Page types usage (6.0) and Search terms (6.4). Reports can be filtered and exported as spreadsheets. Workflows and Workflow tasks reports do not need high-level permissions.
- **Documents and deletion:** Deleted documents cannot be recovered; the Wagtail Guide says so explicitly. Deletion is a hard delete of the record and its file (the file is removed by a post-commit background task). There is no trash or restore. Recovery options: re-upload from a copy, check media storage (MEDIA_ROOT or S3) if the cleanup task failed, restore only that file from a backup, or find copies elsewhere. Document delete rights are tied to edit rights for the owning collection. Images and documents are "owned" by the uploader. Bulk deletion is available by selecting checkboxes in the Documents listing.
- **Redirects:** Settings → Redirects. Add redirects individually, or import a CSV via the import option under "Import and export redirects" (default two columns: "from" and "to"). Exports are CSV or XLSX. Redirects are permanent by default (uncheck Permanent for temporary). A redirect only fires when no page matches the URL, so live pages are not redirected. The command-line `./manage.py import_redirects` (developer docs) has `src`, `site`, `permanent` (default True), `from`/`to` column indexes, `dry_run`, and `ask`. Admin CSV import details beyond the two columns are not documented in the guide; say so. The redirects app must be installed (wagtail.contrib.redirects in INSTALLED_APPS and its middleware in MIDDLEWARE).
- **Users:** Settings → Users. Roles: Administrator, Moderator, Editor by default. Status is active or inactive. Disabling is done by "Select active state" in the bulk action bar, choosing Inactive. An inactive user cannot log in, and only an administrator can change status. Admins can change passwords from the user's edit screen, but the guide recommends the "Forgotten password" link on the login screen. Deleting users is discouraged in favour of inactive status to preserve history.
- **Accessibility and keyboard shortcuts:** Press `?` for the shortcuts dialog (also Help → Keyboard shortcuts). Global: `/` search, `[` toggle sidebar, `Esc` close dialogs. Edit screen: Ctrl/⌘+S save draft, Ctrl/⌘+P live preview, `]` toggle mini-map. Rich text formatting is documented by Draftail (https://www.draftail.org/docs/keyboard-shortcuts). The accessibility page covers the skip link and collapsible sections.
- **Content checks (Checks side panel):** Primarily accessibility, based on the Axe testing engine (https://github.com/dequelabs/axe-core), scanning the rendered page content and aiming at WCAG. Default rules: button-name, input-button-name, link-name, frame-title, empty-heading, empty-table-header, heading-order, p-as-heading, alt-text-quality, empty-meta-description. Content metrics are word count, reading time (language-specific speeds), and LIX readability (Wagtail 7.2+). Wagtail 8.1 adds SEO metadata (meta title and description length) and "View more meta tags" in the Checks panel and userbar.
- **Release notes:** The guide has "New in Wagtail X.Y" pages (e.g., https://guide.wagtail.org/en/releases/new-in-wagtail-8-1/). The most recent in the guide's search index at the time was 8.1 (last modified 2026-11-03). Highlights: 8.1 SEO metadata in Checks, multilingual sitemaps with alternate links, Varying page responses (content negotiation, e.g., Markdown for agents), API v3 improvements (table blocks, nested inline relations, more complete schemas, better Markdown). 8.0 introduced the v3 API for creating, editing and publishing content programmatically. 7.3 added autosave and llms.txt. 7.4 added refined autosave, draft-saving incomplete blocks, customizable listings, and enhanced search. The releases index page itself may have no version list; confirm via search or individual release pages.
- **Other guide facts:** Session time limit default is two weeks. Text search uses Ctrl/⌘+F in the browser. Page listings can show privacy and lock indicators.
